# Phase 5A.1 — Performance Headroom

## Goal
Recover meaningful production JavaScript headroom before adding another Phase 5 feature, without changing the accepted Phase 5A visual hierarchy or product behavior.

## Non-negotiables
- Keep the total production JavaScript gzip ceiling at 365,000 bytes.
- Do not trade JavaScript reduction for a visual regression, broken behavior, or a raised budget.
- Preserve authentication, Coach/Player boundaries, scoring, persistence, events, S&C, Team Store, navigation, and account behavior.
- Preserve the accepted Phase 5A Coach decision hierarchy and Phase 4E presentation system.

## Acceptance
A performance change may pass only when the exact head has:
1. measurable JavaScript gzip reduction with meaningful headroom;
2. the unchanged production performance budget green;
3. Phase 5A and Phase 4F contracts green;
4. production acceptance and auth/demo entry green;
5. fresh 430x932 Player and Coach visual evidence reviewed manually at the established >=9.5/10 standard.

The source-weight report is diagnostic only and does not itself constitute a performance improvement.
